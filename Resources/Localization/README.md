# Localization resources

`pt-BR.json` is the original language of MineDigibyteMobile and the canonical source for every key. On first launch, the app detects the device UI language: Portuguese maps to `pt-BR`, Spanish maps to `es`, and English maps to `en`. Unsupported device languages fall back to the original `pt-BR`. A language explicitly selected in Settings is saved on the device and takes priority over the system language on future launches.

The runtime languages are:

- `pt-BR.json` — Brazilian Portuguese (source language)
- `es.json` — Spanish
- `en.json` — English

## Runtime service

`Localization/LocalizationService.cs` loads and validates the three embedded JSON files, controls the active language, detects the device UI culture when no in-app preference exists (using `CultureInfo.CurrentUICulture`), updates the .NET culture, stores an explicit in-app selection in Preferences, and notifies open pages when the language changes.

Use the XAML extension for labels, buttons, placeholders and page titles:

```xml
xmlns:loc="clr-namespace:MineDigibyteMobile.Localization"
Text="{loc:Translate Key=SomeKey}"
```

Use `LocalizationService.Instance.GetString("SomeKey")` or `.Format("SomeKey", values...)` in C#. `TranslateText` is for existing Brazilian-Portuguese status/log messages generated by the mining and hardware services. It performs a single-pass replacement against the source text so translated words are not translated a second time.

## Adding or changing text

1. Add the new key to all three JSON files.
2. Keep the key names identical in all files.
3. Keep composite-format placeholders identical, including their indexes and format specifiers (for example, `{0:F1}`).
4. Keep PT-BR wording canonical; translate it to Spanish and English rather than using either language as the source.
5. Do not place user-visible sentences directly in XAML or C# when a localization key can be used.

Run this check from the project root before committing:

```powershell
python tools/validate_localization.py
```

The application also validates that the embedded dictionaries contain every PT-BR key and matching placeholders at startup. An incomplete language file is treated as an error instead of silently showing mixed-language content.
